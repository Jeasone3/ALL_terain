# 固定路线执行器

路线：石块 → 大台阶 → U 型隧道 → 栅格 → 左侧外沿 → 减速带 → 草地 → 石块（第二次）→ 右下外沿 → 小台阶 → 防滑带 → 项目 9 斜坡 → 高台停车。方形隧道不进入。

`Route.c` 的 `g_route_plan` 集中记录 24 个道路/项目表项。普通道路和 U 型隧道循迹 PWM 400，其他直通项目 IMU PWM 500，大台阶、小台阶和斜坡先用 600。时间默认 0，因此自动启动被阻止。

## 执行阶段

- 道路：FOLLOW 等待本表项的三帧新路口 → APPROACH 前移后 TURN，或 CROSSING 直穿 → RECOVER 稳定窄线 → 下一表项。
- 直通项目：ENTRY 循迹接近 → 到入口延时后仅发一次 IMU 请求 → OBSTACLE 持续保持入口航向 → 最短时间后连续三帧出口窄线 → RECOVER 再确认三帧 → 下一表项。
- U 型隧道：ENTRY 与 OBSTACLE 都运行灰度 PID，在标定的通行时间内屏蔽路口决策；之后出口窄线稳定再恢复道路识别。
- 项目 9：IMU PWM 600，到标定的登台时间后直接 FINISHED + Car_Stop，不要求蓝色高台上还有黑线。

出口窄线要求：IN3 至 IN6 内连续 1 至 3 路在线，包含 IN4 或 IN5，外侧通道离线。全零、全黑、多段散点与过宽图案不算出口。实际线宽若与此不符，先检查采样再调整此判据。

入口、项目通行和恢复阶段屏蔽路口候选、锁存和事件，避免黑色台阶误判为十字。任意通道有线/无线仍可记录，但 `line_found` 不能单独作为项目完成条件。

## 进度和控制权

`g_route.step_index` 是表项下标，`project_id` 是图中项目编号，二者不同；石块项目编号 1 会出现两次。下标只在动作完成且恢复确认后推进一次，最终项目保持最后一个下标。状态计时每帧 10 ms，阶段切换清零。

外部请求优先、被禁用、停车或故障都会中止路线；不再等待新的路口自动恢复。Route_Enable(0) 本身不停车。Route_Start 只允许停车后从起点重新开始，调用前必须完成 IMU 校准。

超时由 `Car_RouteTimeout()` 请求运动层设置 `CAR_FAULT_ROUTE_TIMEOUT`，统一保存停车前的阶段、计时和 PWM；不会在 Route 里另开电机控制入口。
