# 分段路线执行器

完整路线按用户确认的顺序逐段追加；当前编写九段，默认调试截止段数为 9。使用同一个 g_route_plan 和 Route 调度。

## 阶段与控制

第一段：FOLLOW 等右口 → 短鸣并 ENTRY 循迹 2000 ms → OBSTACLE IMU 4000 ms → RECOVER 循迹并确认两帧中心窄线。

第二段（减速带）：FOLLOW 等十字 → APPROACH 保持航向前移 500 ms → TURN 右转 90°并等待实际完成 → ENTRY 循迹 2000 ms → OBSTACLE 以当前 600 PWM IMU 3000 ms → RECOVER 循迹并确认两帧中心窄线。

第三段：FOLLOW 等减速带后的十字 → 短鸣并直行，ENTRY 灰度循迹 2000 ms → OBSTACLE 以当前 500 PWM IMU 直行 5000 ms → RECOVER 立即循迹并确认两帧中心窄线。

第四段：FOLLOW 等下一个十字 → 短鸣并 APPROACH 以 500 PWM 前移 500 ms → TURN 右转 90°并等待实际完成 → RECOVER 循迹并确认两帧中心窄线。此段使用 RIGHT_TRACK，不进入 ENTRY/OBSTACLE。

第五段：FOLLOW 等 JUNCTION_RIGHT 右弯 → 短鸣、前移 500 ms → IMU 闭环右转 90° → RECOVER 循迹并确认两帧中心窄线；同样不进入项目。

第六段：FOLLOW 等十字 → 短鸣、前移、右转 90° → ENTRY 循迹 1000 ms → OBSTACLE 以 500 PWM IMU 直行 5000 ms → RECOVER 循迹并确认窄线。

第七段：FOLLOW 等十字 → 短鸣并 ENTRY 直行循迹 2000 ms → OBSTACLE 以 500 PWM IMU 直行 4000 ms → RECOVER 循迹并确认窄线。

第八段：保留用户当前表项，FOLLOW 等十字 → 短鸣、前移、左转 90° → ENTRY 配置 1 ms（按 10 ms 控制帧执行）→ OBSTACLE 以 600 PWM IMU 直行 7000 ms → RECOVER 循迹并确认窄线。

第九段：FOLLOW 等下一个十字 → 短鸣、前移、IMU 闭环左转 90° → ENTRY 循迹 1000 ms → OBSTACLE 以 600 PWM IMU 直行 5000 ms → FINAL_TURN 原地 IMU 左转 90° → FINAL_FORWARD 以 500 PWM 保持转后航向直行 3000 ms → FINISHED 停车。

收尾左转不再等待新路口或先前移，直接使用 Car_TurnLeft90(MODE_IMU)。运动层转完当帧自动开始直行，保持 +90°目标；这第一帧计入后面的 3 秒，不重新归零航向。到时只提交一次 Car_Stop，关闭本轮路线，屏幕依次显示 R:END_L、R:END_F、R:DONE，结束日志为 ROUTE_DONE。

每种路口连续两帧相同才确认，同一宽区域只产生一次新事件；连续两帧无路口才解除锁存。FOLLOW 只接受当前段 trigger_junction 指定的类型。等待十字时，若先确认单侧图案，再确认十字，即使新事件已被单侧图案锁存，仍进入前移与转弯；离开 FOLLOW 后不会重复执行。左右单侧路口仍要求新事件。项目、恢复、前移、转弯和 CRUISE 屏蔽路口动作。

非截止段完成后先循迹，再确认出口窄线；IMU 通行计时到达即切回循迹，不要求先发现窄线才结束。窄线需位于 IN3 至 IN6 内，连续 1 至 3 路在线，且包含 IN4 或 IN5；全黑、外侧线、散点和过宽图案不能重新允许下一段识别。

Route 在 IMU 更新前执行，因此转弯完成事件会在下一控制帧观察到；运动层完成帧已经执行的那一帧循迹会计入入口时间，确保 1000/2000 ms 从实际转完开始。动作只在阶段切换时请求一次。

每段指定路口被接受时各短鸣约 100 ms，包括第一个项目结束后的第二段十字。提示音使用独立剩余帧计数，不因阶段重置而延长，同一路口不重复鸣叫。停车或禁用会在控制帧取消提示，IMU 故障最迟下一帧取消。

## 参数与扩展

g_route_plan 每项对应一段：路口动作、段号、IMU PWM、循迹入口时间、IMU 通行时间、阶段超时和指定路口。前八段保留用户当前配置；第九段为 600 PWM、入口 1000 ms、通行 5000 ms。各段阶段超时为 10000 ms；当前前移为 500 PWM、600 ms，循迹基础 PWM 为 500。

IMU_Task.c 的 TURN_MIN_OUT 当前为 250 PWM，本次不修改：尚未进入转弯到位容差时，把 PID 的小输出补足到该值；进入容差后输出零等待两帧确认，随后立即切入指定模式。到位容差在 IMU_Task.h 的 IMU_TURN_DONE_TOLERANCE 统一维护，控制器和状态机共用，当前为严格小于 5°。最低 PWM 仍须按实车转动门槛标定。

Route.h 中 ROUTE_STEP_COUNT 当前为 9；ROUTE_DEBUG_STEP_LIMIT 默认 9，0 表示全部，1 至 8 可截断调试。启动只检查启用范围，未启用段缺参数不会阻止短段测试。RIGHT_TRACK 可以接后续路段，三个不使用的项目参数必须为 0。

调试截止为 1 至 8 段时，仍在该段动作完成后进入 CRUISE 持续循迹。默认 9 和值 0 均执行完整九段及收尾左转、IMU 直行 3 秒停车；收尾阶段屏蔽路口动作，保留转弯超时、IMU 故障及外部接管处理。正常完成后单纯 Enable(1) 不会重新运动，须停车后显式 Route_Start 从起点重启。

## 中止与验证边界

Route_Start 只允许停车时从起点重新启动；调用前 main.c 完成 IMU 初始化和校准检查。任何外部请求、停车、禁用或运动故障中止本轮调度，Enable(1) 不能自动续跑。Route_Enable(0) 本身不停车。

路线每阶段超时由各表项的 timeout_ms 决定；运动层按小于 5°连续两帧判定完成，转弯等待上限为 5 秒。提前完成立即衔接入口循迹，不必等满 5 秒；若 5 秒截止时已进容差，最多额外 10 ms 补足确认，期间离开容差立即故障；未进容差在 5 秒时停车。失败不能跳段。故障捕获保留原阶段与计时；通信恢复不恢复运动。

配置详情见 [分段调试指南](FIXED_ROUTE_GUIDE.md)，验证入口见 [运动测试](../../tests/motion/README.md)。时间配置完整只代表能够启动，前移对齐位置、图案识别和 PWM 均须实车验证。
