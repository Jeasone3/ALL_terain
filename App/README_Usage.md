# 小车运动、分段路线与调试

当前两个启动测试开关均为 0。IMU 初始化与静止校准成功后，从起点循迹出发；默认执行九段路线，最后十字短鸣、左转、循迹 1 秒、PWM600 的 IMU 5 秒后持续循迹，等待手动停车。

## 启动方式

配置位于 Core/Src/main.c 的 USER CODE BEGIN PD：

| 目的 | TRACK_ONLY_TEST_ENABLE | IMU_STRAIGHT_TEST_ENABLE |
| --- | --- | --- |
| 纯灰度循迹 | 1 | 任意，纯循迹优先 |
| 单个项目限时 IMU 测试 | 0 | 1 |
| 当前分段自动路线 | 0 | 0 |

限时测试保留当前 IMU_STRAIGHT_TEST_PWM=700u、IMU_STRAIGHT_TEST_MS=5000u；接受请求后由控制帧计时，到时 TEST_DONE 停车。自动路线时长由 g_route_plan 单独配置。

纯循迹不依赖 IMU 校准成功；限时 IMU 测试和自动路线都要求初始化与校准成功。通信重连不会自动恢复运动。上电校准成功的 200 ms 蜂鸣保留，首个右路口另有一次 100 ms 提示。

## 本次路线

1. 起点循迹，等待两帧确认的右路口；左口和十字不会代替它。
2. 右口确认后短鸣 100 ms，继续灰度循迹 2000 ms，不提交 90°转弯。
3. 第一段 IMU 直行 4000 ms，基础 PWM 600；到时立即恢复循迹。
4. 连续两帧中心窄线后重新接收路口，等待两帧确认的十字；先出现单侧图案不会锁住后续十字动作。
5. 第二段十字确认时短鸣 100 ms，再用现有配置的 PWM 和时间保持航向前移，之后右转 90°。
6. 实际转完后灰度循迹 2000 ms，再按用户当前表项，以 600 PWM 执行减速带 IMU 直行 3000 ms。
7. 减速带结束立即循迹，确认两帧中心窄线后等待下一个十字；接受时短鸣 100 ms，沿前进方向继续灰度循迹 2000 ms。
8. 以用户当前表项的 500 PWM IMU 直行 5000 ms，到时立即恢复循迹；确认两帧中心窄线后才重新接收路口。
9. 下一个十字确认时短鸣 100 ms，以 500 PWM 前移 500 ms，再右转 90°；实际完成后循迹，确认两帧中心窄线后接续第 5 段。
10. 遇到 JUNCTION_RIGHT 右弯，短鸣、前移 500 ms、IMU 闭环右转 90°后循迹；恢复窄线后接下一段。
11. 下一个十字短鸣、前移、右转 90°，循迹 1000 ms，再以 500 PWM IMU 直行 5000 ms，结束后循迹并确认窄线。
12. 再下一个十字短鸣，直行循迹 2000 ms，再以 500 PWM IMU 直行 4000 ms，结束后循迹并确认窄线。
13. 第 8 段保留当前配置：十字短鸣、前移、左转 90°，入口配置 1 ms（按控制帧执行），再以 600 PWM IMU 直行 7000 ms；到时循迹并确认窄线。
14. 下一个十字短鸣一次，沿用前移和 IMU 闭环左转 90°；实际转完后循迹 1000 ms，再以 600 PWM IMU 直行 5000 ms，到时持续循迹，显示 R:CRUISE，记录 DEBUG_END。

灰度循迹基础 PWM 当前为 500，目标是让黑线位于传感器中央。项目入口、通行、恢复和转弯期间屏蔽路口；恢复必须确认中心连续窄线，宽线不能启动下一段。第 4、5 段只转弯后循迹，不运行项目；第 9 段结束不自动停车。新增路段图案、前移位置和实际距离仍需实车确认。

## 实际调用顺序与动作接口

TIM4 每 10 ms → 采样八路灰度 → 接受外部请求 → Route 判断阶段 → 接受 Route 本帧请求 → 必要时更新 IMU → 当前唯一控制器 → 两轮 PWM。

Route 安排阶段；ModeFSM 接受动作、建立航向基准、判断转弯完成并处理故障。Track_Task 与 IMU_Task 互斥写电机，现有 PID 与极性保持原样。

    Car_Track();                       /* 持续灰度循迹 */
    Car_ImuForward(600u);               /* 持续 IMU 直行，由 Route 决定结束时刻 */
    Car_ImuForwardTimed(700u, 5000u);    /* 独立限时测试，到时停车 */
    Car_TurnRight90(MODE_TRACK);        /* 右转完成后自动衔接循迹 */
    Car_TurnLeft90(MODE_TRACK);         /* 左转完成后自动衔接循迹 */
    Car_Stop();                        /* 下一控制帧停车，STOP 优先 */

每次只在阶段切换时提交一次动作，不能把接口依次调用当作队列，也不能在 while(1) 中重复提交。IMU 新动作只在接受时重建航向；转弯完成衔接循迹不重复请求 TRACK。控制路径中不使用 HAL_Delay。

## 扩展、中止与显示

配置位置、调试截止段数和试车步骤见 [分段路线指南](Route/FIXED_ROUTE_GUIDE.md)。

Route_Start 仅允许停车时从起点启动，检查本次启用段；参数无效显示 WAIT_CAL 并保持停车。Route_Enable(0u) 只中止路线调度，不直接停车；需要停车时调用 Car_Stop。外部动作、停车、禁用或故障都不会推进路线，重新 Enable(1) 不能续跑，须停车、放回起点并显式 Route_Start。

OLED 的 S 是段号，从 1 开始；P 是当前路线段的标记，本次为 1 至 9，不是由图片推断的项目编号；N 为当前阶段已完成帧数，乘 10 即毫秒。CRUISE 持续更新计时，但不设置路线超时。ROUTE_TO 为路线阶段超时，TURN_TO 为转弯 5 秒超时。故障画面保存停车前 PWM，实际两轮已经输出零。

转弯等待上限为 5 秒，完成要求角差严格小于 5°且连续两帧；提前完成立即开始后续动作。若第 500 帧已经进入容差但尚未满两帧，最多再补一帧（10 ms）确认；补帧期间一旦离开容差立即故障。未进入容差在 5 秒时停车，PID 和右转 -90°的方向约定沿用原值。

转弯末段在容差外按 TURN_MIN_OUT 补足小输出，当前源码为 250 PWM，本次保留；进入容差后输出零，等待两帧确认后衔接循迹。到位容差由 IMU_Task.h 的 IMU_TURN_DONE_TOLERANCE 统一维护，最低转弯 PWM 位于 IMU_Task.c，须实车标定。

宿主测试和 Keil 编译不替代传感器图案、车身位置、IMU 方向与项目通过能力的实车验证。
