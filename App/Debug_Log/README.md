# OLED 调试日志

`Debug_Log` 只记录状态和事件，不参与运动控制。屏幕使用 6×8 字体，显示 5 行状态和 3 条最近日志；主循环每 100 ms 调用一次 `DebugLog_Display()`。

## 屏幕布局

```text
FAULT L90 R:TURN
Y:+37.2 T:+90.0
E:+52.8 N:300
G:00000000 I:1
L:-427 R:+427
12 I JUNC_L
13 I L90>TRK
16 E TURN_TO
```

| 行 | 字段 | 含义 |
| --- | --- | --- |
| 0 | TRACK / IMU / STOP / FAULT | 运行模式、普通停车或故障 |
| 0 | TRK / FWD / L90 / R90 | 循迹、IMU 直行、左转、右转 |
| 0 | R:FOLLOW / APP / TURN / CROSS | Route 等待条件、转前前移、等待转弯、穿过十字路口 |
| 1 | Y / T | 当前角度、目标角度，单位为度；来自同一姿态基准 |
| 2 | E / N | 目标减当前角度的最短角差、运动动作帧数（每帧 10 ms） |
| 3 | G / I | IN1 至 IN8 的在线情况（1 在线）、IMU 通信就绪（1 就绪） |
| 4 | L / R | 左右轮有符号 PWM 指令；不是编码器实测速度 |
| 5 至 7 | 开机秒数、I/W/E、消息 | 最旧到最新的三条日志，最新记录在最下面 |

循迹会暂停 IMU 采样和解算，`Y/T/E` 显示 `--`，避免误认为旧角度仍在更新。IMU 模式下本帧角度无效时 `Y/E` 显示 `--`；有限的目标角度仍可显示。通信就绪 `I:1` 不等于本帧已取得有效角度。

角度显示范围为 `-999.9` 至 `+999.9` 度，异常的大值或 NaN/无穷值显示 `--`；目标或当前角度无法显示时，相应误差也显示 `--`。该限制只作用于屏幕，不改变控制目标。`N` 保留完整的 `uint32_t` 帧数，最多十位；最短角差最多六列，因此即使 `N` 到达 `4294967295`，整行仍不超过屏幕 21 列。

## 手动记录

```c
#include "Debug_Log.h"

/* 在需要观察的事件发生处调用一次，不在每个控制帧重复调用。 */
DebugLog_Write(LOG_INFO, "CHECK_POINT");
DebugLog_Write(LOG_WARN, "LINE_LOST");
DebugLog_Write(LOG_ERROR, "USER_ERR");
```

每条消息最多保存前 11 个字符，固定三条记录满后覆盖最旧记录。ASCII 32 至 126 原样保存，百分号也是普通文本；其他字节替换为 `?`。空指针、空字符串和非法等级忽略。消息不支持中文字体或 printf 格式参数。

运动层只在动作真正接受、转弯完成、停车和故障时记录；Route 在确认路口、稳定有线和丢线的事件发生时记录。短暂事件在中断中保存，不依赖 100 ms 显示轮询，因此不会因两次显示之间事件消失而漏记。

| 消息 | 含义 |
| --- | --- |
| BOOT / TRACK / IMU_FWD | 开机、接受循迹、接受 IMU 直行 |
| L90>TRK / R90>IMU 等 | 接受左/右转，箭头后为转后模式 |
| DONE>TRK / DONE>IMU | 转弯完成并衔接相应模式 |
| JUNC_L / JUNC_R / CROSS | 确认左路口、右路口或十字路口 |
| LINE_ON / LINE_OFF | 稳定找到线或丢线；运行循迹时丢线为 W，其余为 I |
| STOP | 接受普通停车；故障冻结时不覆盖故障日志 |
| IMU_ERR / TURN_TO / BAD_CMD | IMU 故障、转弯超时或指令参数错误 |

## 故障现场与恢复

故障入口必须先调用 `DebugLog_CaptureFault(fault)`，再修改真实运行状态、清 PID 和停车。函数保存当时的运动模式、IMU 子动作、Route 步骤、角度、目标、帧数、八路灰度、IMU 就绪和两轮 PWM，把副本标记为 `FAULT`，再追加 `IMU_ERR`、`TURN_TO` 或 `BAD_CMD`。

首次故障后现场和三条日志同时冻结；后续普通日志（包括手动 `LOG_ERROR`）和重复故障都不会覆盖。普通停车保持现场。运动层接受新的有效运动动作时调用 `DebugLog_ClearFault()`，解除冻结并保留历史日志；该函数本身不清除真实故障，也不会恢复电机输出。若新动作再次失败，会捕获新的故障现场。

`DebugLog_CaptureFault(CAR_FAULT_NONE)` 不保存现场、不写日志，也不冻结；未知非零故障类型按 `BAD_CMD` 显示。

## 调用节拍与限制

- `DebugLog_Init()` 在 TIM4 启动前只调用一次；初始化记录为空，开机信息由调用者用 `DebugLog_Write(LOG_INFO, "BOOT")` 记录。
- `DebugLog_Write()` 可在主循环或中断调用，只复制有界文本和时间，不做浮点格式化、不访问 OLED、不驱动电机。
- `DebugLog_Display()` 只从主循环每 100 ms 调用，不要放在 TIM4 中断里，也不要让多个任务同时访问 OLED。
- 显示函数短暂屏蔽中断复制一致快照，然后恢复原 PRIMASK，所有格式化和 I2C 通信均在恢复后完成。
- 显示函数返回 `OLED_Update()` 的刷新状态。运行时刷新结果不是 `OLED_OK`，主循环将 `oled_ready` 置零并开始每 1 秒调用 `OLED_Init()` 重连；重连成功后恢复 100 ms 显示。下一次显示会重绘八行，历史日志保留；不要因 OLED 重连再次调用 `DebugLog_Init()`。
- 时间由 `HAL_GetTick()` 除以 1000 得到；约 49.7 天后 HAL 毫秒计数回绕，日志秒数也随之回绕。
- 模块只有三条最近记录，不保存完整运行历史；长时间调试需要在事件处另接串口或其他存储方式。
