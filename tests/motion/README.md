# 运动、分段路线和 OLED 日志验证

在工程根目录运行：

    ./tests/motion/run_tests.ps1
    ./tests/motion/build_keil.ps1

宿主脚本使用 GCC C99，开启 -Wall -Wextra -Werror -pedantic。产物位于 TEMP/all-terrain-motion-tests。Keil 脚本使用当前源码完整重编译，AXF/HEX/日志写入独立临时目录，不覆盖仓库旧构建产物，不烧录硬件。

若沙箱中的 GCC 报“无效的系统 DLL 重定位”，需在获得执行许可后运行同一脚本；该启动错误不能算作源码断言失败或测试通过。

## 宿主覆盖范围

test_motion_route.c 链接真实 ModeFSM、Route、Track_Task、IMU_Task、PID、Com_Limit 和 Debug_Log，只替代外设。真实 PID 包装用于确认每帧最多一个运动控制器、两轮各写一次。

- 请求原子传递 PWM、普通请求最后一个生效、STOP 优先、临界区恢复、外部接管。
- 新鲜 IMU 反馈、无效/NaN/Inf 停车、角度折返、左右转与四种转后模式。
- 当前 5°三帧转弯确认、3 秒超时、截止帧成功优先、转后航向保持。
- 当前 1°直行死区、纠偏方向、不反转与 0 至 1000 的 PWM 边界；不改生产 PID 或纠偏限幅。
- 指定右口与十字各三帧确认，其他图案不能替代，宽区域内类型变化不能重复触发。
- 真实生产参数下，两段各 2000 ms 灰度循迹、4000 ms IMU，第一段 600 PWM、第二段 700 PWM。
- 入口偏线仍执行真实灰度 PID；IMU 内部宽线不执行循迹控制，也不触发下一段。
- 第一段计时到达即恢复循迹，连续三帧中心窄线才重新允许下一路口；全黑、无线、外侧线、散点及过宽图案不能重新启用。
- 十字处先 500 PWM 前移 50 ms，再右转 90°；转动等待不计入第二段入口，实际完成帧的循迹计入 2000 ms，不额外多等一帧。
- 第一段右口只短鸣一次，精确 10 帧，跨阶段不重新计时，第二段不重复；停车、禁用或故障取消短鸣。
- 最终 CRUISE 持续循迹超过 13 秒，不重复请求动作、转弯或蜂鸣，不因路线阶段超时停车。
- 以截止 1、截止 2 和全部已编写段（0）分别编译；截止 1 时第二段故意留非法参数仍能启动，并在第一段后持续循迹。
- 等右口、等十字与恢复窄线的超时停车，恢复截止帧成功优先；正式转弯超时仍由运动层捕获。
- READY、FOLLOW、ENTRY、OBSTACLE、RECOVER、APPROACH、TURN、CRUISE 八阶段外部停车；两段通行、前移和转弯中 IMU 失败均取消路线。
- 禁用、故障、外部接管后不自动恢复；必须停车后显式从起点重启。
- 独立限时测试从请求接受开始，1000 ms 和非整帧 11 ms 的截止边界、故障不被 TEST_DONE 覆盖。

取消与故障场景给测试进程 RAM 注入 30/50 ms 短时间；生产 2000/4000 ms 另有完整帧边界测试，源码参数不因测试修改。

test_debug_log.c 验证日志、有界文本、前台快照、无效角度、故障冻结、断线重绘，以及 21 字符行宽和路线计时冻结。较长段号为合成显示数据，不代表自动运行旧 24 步路线。test_attitude.c 验证姿态复位、ready 条件和 yaw 偏置连续性。

## 验证边界

宿主不执行 main.c 的真实外设初始化和 IMU 静止校准；main.c 默认开关需源码检查和 Keil 编译确认。主机反馈为模拟数据，不能验证实际赛道图案、前移位置、转弯方向、PWM 对应车速或项目通过能力。

默认 TRACK_ONLY_TEST_ENABLE=0u、IMU_STRAIGHT_TEST_ENABLE=0u、ROUTE_DEBUG_STEP_LIMIT=2u；有效 IMU 初始化和校准后应启动前两段路线。独立限时测试仍保留 700 PWM、5000 ms，默认不启用。

2026-10-15 验证：默认截止 2 和全部已编写段（0）各 17 组运动/路线场景通过，单段截止（1）场景通过，5 组日志和 1 组姿态场景通过。GCC 在沙箱外执行；Keil ARMCC 5.06 update 7 完整重编译为 0 Error(s)、0 Warning(s)。未烧录或进行实车验证。
