# 运动、固定路线和 OLED 日志验证

在工程根目录运行：

```powershell
./tests/motion/run_tests.ps1
./tests/motion/build_keil.ps1
```

宿主脚本使用 GCC C99，开启 -Wall -Wextra -Werror -pedantic。产物位于 TEMP/all-terrain-motion-tests。Keil 脚本复制临时工程，使用当前源码完整重编译，AXF/HEX/日志均写入临时目录；不覆盖仓库旧构建产物，不烧录硬件。

## 宿主覆盖范围

test_motion_route.c 链接真实 ModeFSM、Route、Track_Task、IMU_Task、PID、Com_Limit 和 Debug_Log，只替代外设。PID 包装继续运行真实计算，并断言每帧只运行一个运动控制器、两轮各写一次。

- 请求原子传递 PWM、最后普通请求生效、STOP 优先、临界区恢复、外部接管。
- 新鲜 IMU 反馈、无效/NaN/Inf 停车、正负角度折返、原左右转方向。
- 7 度三帧转弯完成、3 秒超时、截止帧成功优先、转后模式和航向。
- 直行 1 度死区、±100 PWM 纠偏、不反转和 0 至 1000 的边界；非法基础 PWM 故障。
- 生产时间默认全 0 时自动启动被阻止；即使只有最后的项目 9 未标定也不能启动。
- 真实 24 步完整路线：10 次项目通行、14 个道路动作；石块两次、U 型循迹、台阶/斜坡 PWM 600，最终项目 9 到时停车。
- 接近入口、最短越障、连续三帧窄线、恢复再确认、同一区域只推进一次。
- 项目内全零/全黑、外侧线、散点和过宽图案不能当出口或路口，IMU 越障不执行循迹丢线降速。
- 路口直行在标定最短时间及稳定出口后及时恢复，不再固定运行 5 秒。
- 项目、等路口和恢复超时触发路线故障；保存停车前 PWM 与路线阶段，不自动恢复。
- 各执行阶段的外部停车、接管和禁用，不推进进度；重新允许不能续跑，显式从起点重新开始。
- 每个项目进入通行阶段只触发一次 100 ms 短鸣，完整路线共 10 次；覆盖 U 型循迹、跨阶段计时、停车/禁用/故障取消，未标定和普通路口不触发提示。
- 单项定时测试从请求接受开始，1000 ms 和非整帧 11 ms 的截止边界，由控制帧停车，故障不会被定时结束覆盖。

测试中给 g_route_plan 注入的几十毫秒是宿主场景参数，每个场景恢复原生产表；不修改生产时间，也不能用于实车。

test_debug_log.c 验证三条日志、有界文本、前台快照、无效角度、故障冻结、断线重绘，以及 S/P/N 最长 21 字符行宽和路线计时冻结。test_attitude.c 验证姿态复位、ready 条件和 yaw 偏置连续性。

## 验证边界

宿主不执行 main.c 的真实外设初始化和 IMU 校准，也不验证赛道图案、实际方向、PWM 对应车速、台阶通过能力、U 型曲线或停止位置。新测试限时执行器在真实 ModeFSM 中接受宿主验证；main.c 的模式选择与校准门限需源码审查和 Keil 编译检查。

当前默认两个测试开关均 0，全部时间参数未标定，正常行为是停车并显示 WAIT_CAL。填满参数只代表配置完整，仍须按固定路线指南逐段试车。
