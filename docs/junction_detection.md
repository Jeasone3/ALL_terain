# 路口识别、诊断与实车调试

本版本用左右两侧的时序证据识别路口，避免必须八路同时在线才识别十字。路口候选期间关闭普通循迹 PID，用 IMU 保持航向；十字默认直行，单侧路口按左右方向转弯。控制和采样由 TIM4 每 10 ms 调度，串口输出和 OLED 显示在主循环完成。

以下参数都是实车待调的起点。源码检查和主机测试不能确认灰度模块极性、实际轮向、IMU 安装方向、PWM 对应车速或真实路口表现。

## 灰度输入和位图

`g_sensor_data[0..7]` 对应 `IN1..IN8`。当前约定原始 GPIO 值 `1` 表示在线，`0` 表示背景；必须先用串口观察实际黑线和白底，确认这个约定适合所接模块。

`raw_mask` 是按 `LINE_RAW_VALUE` 归一化后的在线位图，在线位为 `1`，背景位为 `0`，并不一定等于原始 GPIO 电平。当前默认 `LINE_RAW_VALUE=1`，二者相同。最低位对应 `IN1`，最高位对应 `IN8`。CSV 中的位图以两位十六进制输出，不带 `0x`。

| 通道 | 位 | 掩码 |
| --- | --- | --- |
| IN1 | bit 0 | 01 |
| IN2 | bit 1 | 02 |
| IN3 | bit 2 | 04 |
| IN4 | bit 3 | 08 |
| IN5 | bit 4 | 10 |
| IN6 | bit 5 | 20 |
| IN7 | bit 6 | 40 |
| IN8 | bit 7 | 80 |

例如 `18` 表示只有 IN4、IN5 在线，`FF` 表示八路在线，`00` 表示全部不在线。左右四路分别为 IN1–IN4、IN5–IN8；先确认传感器接线顺序与车体左右一致。

默认单侧证据要求该侧至少三个相邻通道在线，且 IN4、IN5 至少一路在线。每侧最近三帧中至少两帧满足判据才形成有效证据。八路同时在线可以提供左右证据，但不是十字识别的唯一输入。

用于取消候选和恢复循迹的窄线必须同时满足：至少一路在线、所有在线点只位于 IN3–IN6、IN4 或 IN5 在线、在线总数不超过三个，并且在线点是一段连续区间。只有中间通道为 `1` 或在线总数较少，单独都不足以判定窄线。

## 状态和动作

| 编号 | 枚举 | OLED | 行为 |
| --- | --- | --- | --- |
| 0 | STATE_NORMAL_TRACK | NORMAL_TRACK | 普通循迹并寻找路口候选 |
| 1 | STATE_CROSS | CROSS | 已确认十字的过渡状态，默认选择直行 |
| 2 | STATE_TURN_LEFT | TURN_LEFT | 用 IMU 转到相对目标 +90° |
| 3 | STATE_TURN_RIGHT | TURN_RIGHT | 用 IMU 转到相对目标 -90° |
| 4 | STATE_FORWARD | FORWARD | 驶离路口并等待窄线恢复 |
| 5 | STATE_JUNCTION_PENDING | PENDING | 收集左右时序证据并保持进入时航向 |
| 6 | STATE_APPROACH_TURN | APPROACH | 转弯前推进到路口中心 |
| 7 | STATE_FAULT_STOP | FAULT_STOP | 故障停车 |

任一侧出现单帧空间特征就进入候选状态，首帧计为候选第 1 帧；进入候选后才进行最近三帧的两票确认。左右有效证据都还处于八帧关联窗口内时，可立即确认十字，不必等满十二帧；例如连续两帧 `FF` 就能确认十字。单侧路口到候选第十二帧才归类，且该侧证据仍须有效；此时两侧证据都已过期则故障停车。若先重新回到窄线并连续保持三帧，候选可取消。

确认单侧路口后，在完成总推进时间后才开始转弯；候选期和转弯前推进合计计算，不再叠加旧版本额外 400 ms 直行。当前确认窗口与总推进同为十二帧，正常单侧确认通常直接进入转弯；减小确认窗口、增大总推进时，才会在 APPROACH 状态补足剩余推进。

离开路口后，从 FORWARD 的第 5 帧起才累计连续窄线帧数；即使输入一直是窄线，也要到第 8 帧满足连续四帧后才能恢复普通循迹。恢复前保持禁止重新触发路口，避免同一条横线重复计数。转弯要连续满足角度容差才能结束，随后也通过驶离和找线阶段恢复普通循迹。

故障停车不会因主循环重新初始化 IMU 成功就自动恢复电机动作。先排除故障，确认车体放置与传感器输入，再重新启动测试。

## 默认参数

| 条件 | 默认值 | 调试重点 |
| --- | --- | --- |
| 控制节拍 | 10 ms | TIM4 负责调度 |
| 单侧空间证据 | 至少三个相邻通道在线且中间有线 | 核对极性、通道顺序和线宽 |
| 单侧时间投票 | 最近三帧至少两票 | 压制一帧抖动，代价是检测延迟 |
| 左右证据关联窗口 | 各侧最近有效证据距当前不超过八帧，80 ms | 适应车体倾斜或通道先后经过横线 |
| 候选确认窗口 | 十二帧，120 ms | 单侧证据观察时间 |
| 候选取消 | 窄线连续三帧 | 避免短暂侧边干扰被当成转弯 |
| 候选中心失联 | 连续三帧 | 故障停车，避免丢线仍推进 |
| 候选最大偏航 | 15° | 故障停车，限制候选期走偏 |
| 候选与转弯前总推进 | 十二帧，120 ms | 与路口几何和车速联合调整 |
| 候选与转弯前速度 | 左右基础 PWM 250 | 相同速度，航向环可产生差速 |
| 驶离路口最短时间 | 五帧，50 ms | 避免立即重新循迹或重复触发 |
| 恢复普通循迹 | 窄线连续四帧 | 不能只按固定时间直接恢复 |
| 驶离与找线超时 | 一百帧，1 s | 超时停车 |
| 转弯完成 | 误差小于 7°，连续三帧 | 避免单帧经过目标就提前结束 |
| 转弯超时 | 二百帧，2 s | 角度不收敛时停车 |
| OLED 刷新 | 200 ms | 显示状态和带符号目标角 |

推进距离由实际车速决定，PWM 250 不是距离单位。应先低速测出候选到路口中心的距离，再调整总推进时间；不要单纯增加延时去掩盖漏检。

## 串口诊断

USART2：`115200`、`8N1`。`PA2` 为 TX、`PA3` 为 RX。接 USB 转串口时交叉连接 TX/RX 并共地，使用与板卡兼容的电平。

每轮主循环最多取四条诊断帧，用整数 CSV 输出；TIM4 中断不执行 `printf`。格式为：

```text
J,tick,mask,state,leftVotes,rightVotes,event,count,yaw10,fault,imuReady
```

| 字段 | 含义 |
| --- | --- |
| J | 诊断记录前缀 |
| tick | 状态机控制节拍累计时间，每帧增加 10 ms，首条为 10；不是 HAL 系统时间或实测中断间隔 |
| mask | 八路归一化在线位图，两位十六进制 |
| state | 上表的状态编号 |
| leftVotes / rightVotes | 左右最近三帧的有效票数，范围 0–3 |
| event | 最近确认的路口事件编号 |
| count | 已确认路口的累计次数，用于识别重复触发 |
| yaw10 | 航向角乘以十后取整数，例如 -123 表示 -12.3° |
| fault | 故障编号 |
| imuReady | IMU 通信状态，1 为可通信，0 为不可通信 |

| 事件编号 | 枚举 | 含义 |
| --- | --- | --- |
| 0 | JUNCTION_NONE | 尚无已确认路口事件 |
| 1 | JUNCTION_CROSS | 十字路口 |
| 2 | JUNCTION_LEFT | 左侧路口 |
| 3 | JUNCTION_RIGHT | 右侧路口 |

| 故障编号 | 枚举 | 排查方向 |
| --- | --- | --- |
| 0 | MODE_FAULT_NONE | 无故障 |
| 1 | MODE_FAULT_IMU | 检查 IMU 接线、供电、通信和初始化 |
| 2 | MODE_FAULT_HEADING | 候选期偏航过大，核对轮向和角度纠偏方向 |
| 3 | MODE_FAULT_CENTER_LOST | 候选期中间线持续丢失，检查极性、速度和横线几何 |
| 4 | MODE_FAULT_AMBIGUOUS | 候选证据无法可靠归类，检查关联窗口和干扰形状 |
| 5 | MODE_FAULT_TURN_TIMEOUT | 转弯不收敛，核对实际角变化、符号和 PID |
| 6 | MODE_FAULT_EXIT_TIMEOUT | 驶离后未重新找到窄线，检查推进距离与线宽 |
| 7 | MODE_FAULT_INVALID_STATE | 状态值非法，检查状态写入与内存问题 |

正常循迹和故障停车状态不更新 IMU 航向，因此这些状态下 `yaw10` 可能保持上次值，不能把它当成本帧实际航向。`Target` 是目标角，不是实际角；实际角要看角度控制状态下、IMU 可通信时的串口记录。

`CROSS` 仍是短暂过渡状态，OLED 可能错过它；应同时看串口事件编号和累计次数，不能只凭屏幕判断是否识别。日志队列容量有限，OLED 或串口阻塞可能导致记录丢弃。`ModeFSM_GetSnapshot()` 的 `debug_dropped` 记录丢弃次数，可在调试器查看；日志缺行不等于控制节拍未执行。

## 实车验证顺序

1. 抬起车轮，逐个遮挡或放置 IN1–IN8，确认位图每次只改变对应位；分别测试黑线、白底和无输入，确认在线极性。
2. 抬起车轮验证正 PWM、负 PWM 的实际轮向。进入候选时轻转车体，确认角度纠偏会减小误差，再测试自动转弯。
3. 低速经过正交十字，保存从 NORMAL_TRACK、PENDING、十字事件到 FORWARD、恢复循迹的记录。每次经过同一路口，累计次数应只增加一次。
4. 以小倾角经过十字，让左右侧先后在线。两侧证据在关联窗口内出现时应确认十字；超出窗口时观察故障或归类结果，按真实道路尺寸调整参数。
5. 分别测试仅左侧、仅右侧路口，确认候选期和转弯前推进的总时间，以及 ±90° 目标对应的实际转向。
6. 测试普通弯道、短划痕和单帧灰度抖动；观察是否取消候选、是否误计数，以及恢复窄线的时序。
7. 测试较宽横线、停车后仍压在横线上的情况。确认尚未恢复窄线时不会反复触发，找线超时后会停车。
8. 先抬起车轮测试候选期间 IMU 通信失败、中心失联和转弯超时，确认进入 FAULT_STOP、两轮停止；再做低速地面测试。

有限的八路数字灰度输入不能保证区分真正路口与长划痕、宽黑斑或形状相近的假路口。只要这些干扰在空间和时间上产生相同证据，仍可能被识别成路口；需要结合赛道约束、位置或额外传感器处理，不能仅靠增加投票帧数作保证。
