# OLED 驱动与小车调试使用说明

## 1. 工程中如何使用

当前工程已经接入，不需要重新添加主循环代码。Keil 项目已添加通用驱动、字库和调试模块。

上电后左右按键依次切换：运行、路口、历史、故障、性能。屏幕采用 ASCII 缩写，下面给出中文含义。

| 按键 | 作用 |
|---|---|
| LEFT / RIGHT | 循环切换页面 |
| UP / DOWN | 历史页向旧 / 新记录移动 |
| OK | 冻结 / 恢复显示，标题变成 HOLD / LIVE |

按键在 PA8..PA12，分别是 UP、DOWN、RIGHT、OK、LEFT；工程配置上拉输入，按下应接地。消抖 30ms，长按只触发一次。按键只操作显示，不启动车辆、不恢复故障、不修改控制参数。HOLD 期间车辆和日志继续运行，冻结的历史副本最多 32 条。新故障会解除冻结并切入故障页，随后可以手动浏览其他页。

## 2. 五个页面怎么看

### 运行页 RUN

| 字段 | 意义 |
|---|---|
| S | 控制状态：TRACK 循迹、PENDING 待确认、CROSS 十字过渡、LEFT/RIGHT 转弯、APPROACH 推进、EXIT 驶离、STOP 停车 |
| G | IN1→IN8 的归一化在线位图；1 在线，0 离线，已经处理 GPIO 极性 |
| PWM | 左右轮的有符号 PWM 指令，范围 -1000..1000，不是实测车速 |
| IMU | 通信状态，1 正常，0 不可用 |
| Y | 实际相对航向，单位度；FRESH 本控制帧更新，STALE 是此前留下的角度，INVALID 无有效数据 |
| T | 目标航向，正负号保留；不是测量值 |
| EV / # | 最近确认的路口和累计确认次数，经过路口后仍保留 |
| DROP | 诊断队列丢弃的帧数，不等于控制丢帧 |

屏幕每 200ms 采集一次显示快照。FRESH 表示该快照对应的控制帧更新了角度，并不保证看到屏幕的时刻传感器仍在更新。正常循迹不解算 IMU，角度显示 STALE 是正常的。

### 路口页 JUNCTION

- N：当前状态的局部帧数，名义每帧 10ms。
- VOTE：最近三帧符合左右空间特征的帧数，范围 0..3，不是亮起的探头数量。
- FRESH：对应侧是否存在仍在关联窗口内的有效证据。
- AGE：证据年龄，单位帧；255 表示未取得或当前状态不适用。只有 PENDING 阶段展示有效证据年龄。
- CENTER：中心线连续丢失帧数 / 停车阈值。
- LINE：连续窄线帧数；TURN：连续角度到位帧数。
- ADV：候选和追加推进的累计前进帧数 / 推进目标。

短暂候选可能在页面下一次更新前结束，此时使用历史页和串口日志复查，不应只盯实时票数。

### 历史页 HISTORY

保存最近 32 条状态变化、路口确认、候选取消和故障，最新记录在上方。每行左侧数字是控制节拍编号（名义毫秒时间除以 10）；不是墙钟或实际运行耗时。

`CROSS` 确认会被记录，即使实时页来不及显示该状态。`CANCEL` 表示连续记录中 PENDING 恢复 TRACK。`LOG_GAP` 表示相邻诊断记录相差不止一帧；存在缺口时不推断漏掉的取消过程。历史是有限记录，队列溢出期间的每个瞬时变化无法保证保留；EV/# 和故障快照仍可用于检查最后结果。

### 故障页 FAULT

| 编号 | 名称 | 含义 |
|---|---|---|
| 0 | NONE | 无故障 |
| 1 | IMU_INVALID | 通信失败或姿态异常 |
| 2 | HEADING_ERROR | 候选 / 推进偏航过大 |
| 3 | CENTER_LOST | 中心线连续缺失 |
| 4 | AMBIGUOUS | 确认期限结束仍无可靠方向 |
| 5 | TURN_TIMEOUT | 转弯超时 |
| 6 | EXIT_TIMEOUT | 驶离 / 找线超时 |
| 7 | INVALID_STATE | 非法状态 |

屏幕故障页显示同一快照中的灰度、IMU、角度、最后事件及累计通信错误。显示系统不会自动解除控制器的停车锁存。

### 性能页 PERF

| 字段 | 单位与含义 |
|---|---|
| CPU | 配置的系统时钟，当前 72MHz，不是 CPU 使用率 |
| CTL | 最近一次 ModeFSM_Tick 调用的耗时，微秒 |
| MAX | 从初始化以来最大的控制调用耗时，微秒 |
| OVER10ms | 控制调用耗时达到或超过 10ms 的次数 |
| GAPMAX | 两次 TIM4 回调开始之间的最大间隔，微秒 |
| LATE11ms | 回调开始间隔超过名义周期 110% 的次数，当前阈值 11ms |
| DROP / I2C | 日志丢帧和 OLED 通信错误累计值 |

控制耗时包括传感器读取、姿态解算、控制输出、诊断入队与快照，以及期间被更高优先级中断抢占的时间；不包含 HAL 定时器分发和前台 OLED / 串口执行时间。它不是完整 CPU 占用率。到达间隔异常也不是精确漏拍数。调试断点、暂停或关闭 DWT 后读数不可靠。

本工程启动时已有 `Delay_Init()` 开启 DWT。测量采用无符号差值，允许一次计数回绕；在 72MHz 下不能用它可靠计算跨越多次回绕的长期停顿。统计只随 `ModeFSM_Init()` 清零，不用按键清零，因为这个初始化接口同时重置车辆状态。

建议让正常工况控制最大耗时低于 5ms，以保留余量。这是验收目标，不是已测得的结果。若 OVER10ms 增长，先检查软件 I2C 和姿态解算；若只有 DROP 增长，先检查串口、显示和前台重试的阻塞。

## 3. 路口调试实例

1. 正常线形先确认 G 的 IN1→IN8 顺序和在线极性正确。
2. 左侧先经过横线：状态进入 PENDING，左票数从 1 到 2，左 FRESH 变成 1。
3. 在证据窗口内右侧也取得两票：确认 CROSS，累计 # 加一；不要求某一帧八路同时在线。
4. 历史出现 CROSS、EXIT、TRACK，说明已确认十字并恢复循迹。
5. 只有瞬时划痕时，可能短暂 PENDING，随后 CANCEL；没有确认事件，# 不增加。
6. 若停车，先读故障名。CENTER_LOST 和 EXIT_TIMEOUT 对应不同阶段，不应一起调整同一个时间参数。

需要精确到 10ms 的分析时，配合原有串口 CSV。OLED 与串口共享主循环取出的记录，不会分别消费同一队列。

## 4. 最小绘图示例

以下示例用于另一个应用。当前小车已经由 OLED_Debug 管理同一设备，不要把示例与调试模块同时写到一个画布。

```c
#include "Int_OLED.h"

/* MX_I2C1_Init() 已完成，之后只初始化一次。 */
(void)IntOLED_Init(HAL_GetTick());
OLED_Device *display = IntOLED_GetDevice();

OLED_Clear(display, 0);                         /* 只清画布，不立即通信 */
OLED_DrawText(display, 0, 0, "Hello", OLED_FONT_6X8);
OLED_Printf(display, 0, 16, OLED_FONT_8X16, "PWM:%d", -250);
OLED_DrawRect(display, 0, 40, 100, 16, 0, 1);
OLED_DrawLine(display, 2, 42, 90, 52, 1);
(void)OLED_Present(display);                    /* 提交一个发送副本 */

while (1) {
    (void)OLED_Service(display, HAL_GetTick()); /* 推进上电等待、重试和逐页发送 */
    /* 这里继续执行其他前台工作，不用 HAL_Delay 等待整屏刷新。 */
}
```

### 接口规则

- 原点为左上角，x 向右、y 向下；两者都是像素坐标，旧函数的页坐标不再使用。
- 6×8 字体一行 21 字符；8×16 字体一行 16 字符。换行符明确移动一个字体高度，不自动横向换行。
- 文字覆盖整个字符单元；整页内容变短时先清画布再重画。驱动提交时比较实际像素，相同画面不会重复发送。
- `OLED_Printf` 内部最多接收 95 字符，超出返回参数错误，不提交截断字符串。浮点 `%f` 是否可用取决于 C 库，推荐用整数或十分之一度表示角度。
- 位图长度至少 `width * ((height + 7) / 8)`，按每 8 行一页存储，每页依次存各列，字节 bit0 是最上面的像素。
- 初始化返回 OK 只表示参数正确；`OLED_GetStatus().ready` 表示初始化命令已发送成功，不是屏幕自检成功。
- `OLED_Present` 返回 BUSY 时，前一画面仍在发送；画布的新内容保留，前台继续 Service，空闲后重新 Present。
- `OLED_Service` 每次最多发送一页，仍是同步阻塞通信，不是 DMA。主循环中的中断保持正常开启，不能在 ISR 或关中断期间调用。
- 同一设备只由一个执行上下文使用；多任务中需由应用串行化绘图和发送。回调必须同步完成，不能留下数据指针用于异步传输。

## 5. 移植到其他项目

复制 `Com/Com_OLED` 中的 `oled.c`、`oled.h`、`oled_font.c`、`oled_font.h`，加入新工程与头文件路径。它们只依赖标准 C，不需要复制小车的 Mode_FSM、按键或 STM32 适配模块。

提供一个通信回调，并给每块屏幕单独分配设备对象：

```c
static OLED_Device display; /* 静态存放，不要把约 2KiB 的对象放在小栈上 */

static OLED_Result write_port(void *user, uint8_t address7, uint8_t control,
                              const uint8_t *data, uint16_t length,
                              uint32_t timeout_ms)
{
    /* 在此实现：I2C START、address7、control、length 字节 data、STOP。
     * 根据平台接口要求转换地址；只转换一次。每步失败都应返回 IO_ERROR。
     * user 可以指向 I2C 实例。实现必须同步完成并具有有限超时。 */
    return your_i2c_write(user, address7, control, data, length, timeout_ms)
        ? OLED_OK : OLED_IO_ERROR;
}

static const uint8_t panel_commands[] = { /* 按实际屏幕数据手册填写 */ 0xae, 0xaf };
/* 上面的两条命令只是结构示例，不是可直接用于所有屏幕的完整初始化表。 */
static const OLED_Config config = {
    128, 64, 0, 0x3c, panel_commands, sizeof(panel_commands), 20, 500, 100
};
static const OLED_Port port = {write_port, NULL};

(void)OLED_Init(&display, &config, &port, your_millisecond_tick());
/* 然后按前面的绘图示例工作，持续传入单调递增的 uint32_t 毫秒时间。 */
```

通信回调的 control 为 0x00（命令）或 0x40（数据）；在 STM32 HAL 适配层，它被作为 Mem_Write 的首个控制字节发送。地址 0x3C 是七位地址，HAL 接口使用 0x78。其他库可能直接接收 0x3C，不能一律左移。

配置、平台结构体会复制到设备对象，但初始化命令数组和 user 指向对象需要持续有效。支持宽度 1..128、高度 8..64 且为 8 的倍数；这只是画布范围，必须再检查实际屏幕控制器和初始化表。发送使用页地址命令 B0..B7 及高低列命令，不支持直接替换为彩色或不同寻址协议的显示控制器。

当前屏幕芯片未确认，适配层保留原电气参数和扫描方向，但将 `0x20,0x10` 修正为 `0x20,0x02`，让寻址模式与新驱动的按页发送匹配。按 [Solomon Systech SSD1306 数据手册](https://cdn-shop.adafruit.com/datasheets/SSD1306.pdf) 的寻址命令表，参数低两位 10 才是页模式，原 0x10 的低两位 00 会选择水平模式。若实际芯片为 SH1106，仍需匹配其初始化和列偏移；目前没有上板验证，不能宣称两种控制器都已适配。

每个设备有 2048 字节双缓冲，另加配置和状态；主机 64 位编译时对象为 2120 字节，ARM 32 位以构建报告为准。字库放在只读区。通用绘图层不使用堆，小车历史采用固定环形数组。改用 RTOS 时，时间源和单一显示任务由应用提供。

## 6. 常见问题

| 现象 | 优先检查 |
|---|---|
| 黑屏 | 电源、接线、I2C 外设初始化、七位地址、芯片初始化命令；串口或调试器查看设备 error_count |
| 画面左右偏移或缺列 | 控制芯片、column_offset、初始化表的寻址模式 |
| 屏幕闪烁或变慢 | 是否逐帧完整更新、是否重复 Init、是否在多个地方绘制同一对象 |
| 短文字留下尾巴 | 应用是否先清对应区域或整张画布再重画 |
| Y 不动 | 是否处于普通循迹或故障状态，检查 STALE / INVALID 与 IMU 状态 |
| 无法翻页 | 五键是否接地有效、GPIO 配置是否被修改；OLED 故障不会停止前台键扫描 |
| 控制正常但历史缺失 | DROP / LOG_GAP、串口阻塞、前台 IMU 重试；屏幕不能保证保存溢出期间所有事件 |

屏幕失联后发送失败立即结束本轮，500ms 后重试。20ms 是每次总线调用的超时，不是整张画面刷新的总时限；100kHz 下整屏发送需要多轮服务。所有 OLED 发送均在前台，错误不会触发车辆故障恢复。

## 7. 软件检查与上板验收

运行 `checks/run_checks.ps1`：通用层独立编译、驱动和真实 UI 检查、归档状态机回归、ARM 语法检查。用户删除的 tests 不会恢复；旧样例从 Git HEAD 提取到临时目录。以后提交删除后，HEAD 不再含旧测试时，会明确提示跳过归档控制回归，继续运行 OLED 与 ARM 检查。

运行 `checks/build_keil.ps1`：在临时目录完整重建当前项目并生成 AXF / HEX；源码从工作区读取，不替换原工程的输出文件，也不删除产物。

上板仍需确认：屏幕方向和列偏移、五个按键、灰度顺序、负号、短暂路口历史、故障抢占冻结、OLED 断开后的控制与重试、转弯时 MAX 和 OVER10ms。主机检查和完整编译不能替代这些硬件检查。
